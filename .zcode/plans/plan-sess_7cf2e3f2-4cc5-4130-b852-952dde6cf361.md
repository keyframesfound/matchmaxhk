# Education fields driven by real tutor data

**Goal:** the public university / secondary-school / major filter dropdowns list the actual values our tutors have (per your "only real values" choice — hardcoded buckets go away), and both the admin TutorEditor and the tutor-facing My Tutor Profile get dropdowns fed from existing DB values with "add new" still allowed, so the same university/school/major gets reused instead of re-typed with new spellings.

## 1. `src/features/tutors/education-filters.ts` — helpers + matching
- Add a structural `EducationValueRow` type and `collectEducationValueSets(rows)` → `{ universities, highSchools, majors }`: trim, drop empties, case-insensitive dedupe, sorted by tutor count (desc) then alphabetically.
- Extend the editor builders `universityEditorOptions` / `highSchoolEditorOptions` / `majorEditorOptions` with an optional `dbValues` param — merge order: current value, DB values, canonical suggestions (case-insensitive dedupe).
- Matching becomes exact (case/whitespace-collapsed equality) over the tutor's fields — same semantics the major filter already uses (issue #23): `matchesUniversityFilter` over undergrad+postgrad university, `matchesHighSchoolFilter` over secondary school. Drop the comma-splitting `matchesAny*` wrappers (the UI is single-select) and update the route to call the single-value matchers.
- Keep the private matchers (`UNIVERSITY_MATCHERS` etc.) solely to power `isElitePedigree`, so the education empty-state fallback list behaves exactly as today.
- Remove the now-unused `UNIVERSITY_FILTER_OPTIONS` / `HIGH_SCHOOL_FILTER_OPTIONS` exports.

## 2. Public filter UI — `src/components/search/tutors-search.tsx`
- New optional `educationValues` prop. University / high school / major dropdowns (desktop FiltersDialog + mobile overlay) list "Any" + the real values (value = label = raw text). Major keeps `allowCustom` so parents can type any major; university/school become pure pick-from-real-values (searchable, so variants are findable).

## 3. Route wiring
- `tutors.index.tsx`: compute `collectEducationValueSets(tutors)` in a `useMemo` and pass to both search components; swap to the single-value matchers.
- `index.tsx` (homepage): same computation from its existing `publishedTutors` query, passed to its search bar/overlay.

## 4. Admin editor
- `_authenticated.admin.tutors.tsx`: compute the same sets from `tutors` (fetchAllTutors — includes unpublished) via `useMemo` (same pattern as the existing subjectOptions), pass as a new `educationValues` prop to `<TutorEditor>` (line ~485).
- `TutorEditor.tsx`: accept the prop and feed it into the 5 education selects (undergrad/postgrad university, secondary school, undergrad/postgrad degree). `allowCustom` stays — admins can add a new institution; once saved it shows up in everyone's dropdown, so repeat tutors pick instead of retype.

## 5. Tutor-facing settings — `my-tutor-profile-section.tsx`
- Swap the three plain text inputs (secondary school ~line 307, undergrad university ~318, undergrad degree ~329) to `SearchableSelect allowCustom`.
- Add a small `fetchEducationValues()` query in `queries.ts` (selects only the 5 education columns from `tutors`; RLS exposes published rows) cached under `["tutors", "education-values"]`; options = DB values + canonical suggestions.
